SOP Title:         [e.g. Production Deployment & Sprint Milestone Release Procedure]
Document ID:       12L-SOP-[OPS / ENG / SEC]-[001]
Version:           v1.0 (2026.1)
Effective Date:    [Date: e.g. 15 March 2026]
Owner / Author:    [Author Name & Title: e.g. Lwandiso George, COO & Cloud Architect]
Approved By:       [Approver: e.g. Nkosinathi Ngwenya, CTO / Jacky Mpoka, Project Lead]
Review Cycle:      Bi-Annual (Every 6 Months)

1. PURPOSE & OBJECTIVE
This Standard Operating Procedure establishes the mandatory protocol for [Brief 1-2 sentence objective: e.g. staging, testing, security scanning, and deploying production code updates across 12 Links repositories and client environments to guarantee zero-downtime releases and complete auditability].

2. SCOPE & APPLICABILITY
This SOP applies to all 12 Links core engineers, sub-contractors, and technical leads operating on internal products (including chuse.) and client engineering projects.

3. REQUIRED TOOLS, ACCOUNTS & ACCESS
• Version Control: Git / GitHub (https://github.com/12Links) with mandatory branch protection.
• CI/CD Pipeline: GitHub Actions automated linting, typecheck, and unit testing workflows.
• Cloud Infrastructure: Vercel Edge Network / AWS Cape Town (`af-south-1`) / Ubuntu Linux LTS hosts.
• Secret Management: Encrypted `.env` injection (zero secrets committed to version control).
• Communication: Internal engineering team channel & milestone sign-off register.

4. STEP-BY-STEP OPERATIONAL WORKFLOW

STAGE 1: PRE-RELEASE CODE AUDIT & TYPECHECK
1.1 Branch Verification: Ensure all feature commits are squashed and rebased onto a clean `release/vX.X` branch. Direct pushes to `main` are strictly blocked.
1.2 Automated Verification: Run the test and typecheck pipeline locally:
    `npm run typecheck`  (Must exit with 0 errors)
    `npm run build`      (Must compile cleanly within performance thresholds)
1.3 Security & Secret Scan: Verify that zero API keys, database credentials, or private customer records exist in code or commit history.

STAGE 2: STAGING VERIFICATION & INTERNAL REVIEW
2.1 Staging Deployment: Push release branch to generate an isolated staging preview URL.
2.2 Functional Walkthrough: Project Lead ([Jacky Mpoka]) conducts end-to-end flow verification:
    • Browser UI responsiveness & WCAG AA contrast check;
    • API response latency and database query indexing;
    • Data persistence & offline synchronization boundaries.
2.3 Sign-off: Record internal QA sign-off in the sprint register before touching production.

STAGE 3: PRODUCTION PROMOTION & IN-COUNTRY DEPLOYMENT
3.1 Promotion Trigger: Merge approved PR into `main` using fast-forward or squash merge.
3.2 Atomic Rollout: Verify deployment orchestration on production host/CDN.
3.3 Healthcheck Verification: Check live status endpoints:
    • Verify HTTPS SSL certificates and HTTP/2 headers;
    • Confirm regional routing to South African endpoints (`af-south-1` or Vercel Edge);
    • Validate live database migrations and connection pools.

STAGE 4: CLIENT NOTIFICATION & MILESTONE LOGGING
4.1 Release Notes: Publish concise release notes detailing changes, fixes, and API versions.
4.2 Client Update: Notify client technical leads with live staging/production links.
4.3 Repository Tagging: Tag the Git commit with the semantic release version: `git tag -a v2026.X -m "Release v2026.X"`.

5. EMERGENCY ROLLBACK & CONTINGENCY PROCEDURE
If a critical defect or security vulnerability is detected in production:
5.1 Immediate Revert: Revert the production deployment immediately via one-click rollback on the hosting orchestrator or by deploying the previous Git release tag: `git revert HEAD`.
5.2 Incident Containment: Switch DNS or traffic routing to maintenance fallback if database corruption is suspected.
5.3 Root-Cause Analysis (RCA): Lead architect shall conduct an RCA within 24 hours, documenting the breakdown and remediation steps in the 12 Links incident log.

6. COMPLIANCE & AUDIT LOGGING
All deployments and operational changes must maintain automated logs for a minimum of 12 (twelve) months in accordance with 12 Links internal security controls and POPIA compliance.
